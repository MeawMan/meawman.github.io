# Brishti IDF

**Rainfall intensity–duration–frequency (IDF) analysis that runs entirely in your web browser.**
Load a rainfall record (1-minute to daily, tipping-bucket logs, or annual-maximum tables). Check its quality, extract annual maxima, compare probability distributions, fit IDF equations, estimate short-duration rainfall from daily data, build design storms, and export tables, figures and a methods report. Nothing is uploaded: the data never leave your computer.

*Brishti* (বৃষ্টি) means rain in Bangla. The tool was built with Bangladesh's data situation in mind (many daily gauges, few sub-daily ones), but works anywhere.

Live: **https://meawman.github.io/tools/brishti-idf/** (part of the portfolio of Mahfujur Rahman Joy).

> **Status: version 0.2.0.** The numerical core is tested against SciPy (see `docs/VALIDATION.md`). Methods that estimate sub-daily rainfall from daily data are **not validated for Bangladesh**; read the Methods screen, `docs/HOLDOUT.md` and `docs/LIMITATIONS.md` before using results for design.

### New in 0.2.0
- Three-parameter log-normal; GEV with a shape you fix (e.g. a regional value); ranking by AICc, BIC, A², PPCC or KS; choice of plotting position.
- Peaks over threshold (generalised Pareto or exponential excesses, Poisson arrivals) with a threshold-stability table, usable for the design table.
- Grubbs–Beck outlier screening (flags only).
- An “i” button on every option, a Methods and references screen with the equations, and a copyable methods paragraph.
- Portfolio header, fonts and colours; light/dark theme shared with the portfolio.

## Quick start

1. Open the tool (your GitHub Pages address, or a local server; see below).
2. On **Your data**, drop a CSV/XLSX file, paste data, or click an example. Check the column mapping and press **Add to project**.
3. Work down the steps on the left. **Guided** mode shows recommended settings; **Expert** mode shows every option.
4. On **Report and export**, copy the methods paragraph, and download the report (HTML; print to PDF), the workbook (XLSX), the design table (CSV) and the project file (JSON). Opening the project file later reproduces the same results, including random seeds.
5. Click any **i** button for a short explanation of that option; the **Methods and references** step has the equations and sources.

### Accepted input layouts
| Layout | Example header | Sample file |
|---|---|---|
| Date-time + rainfall | `datetime,rain_mm` | `data/sample_hourly_synthetic.csv` |
| Separate date and time, or year/month/day(/hour/minute) columns | `date,time,rain` | – |
| BMD-style daily sheet | `Station,Year,Month,1,2,…,31` | `data/sample_daily_bmd_wide_synthetic.csv` |
| Annual-maximum table | `Year,15min,30min,1h,…,24h` | `data/sample_ams_table_synthetic.csv` |
| Several stations in one file | `station,date,rain_mm` | `data/sample_multistation_daily_synthetic.csv` |
| Tipping-bucket log | one row per tip | – |

Missing values may be blank, `NA`, `-999` or `***`; trace (`T`) is read as 0. All sample files are **synthetic** (generated by `tools/make_samples.js`). The only real record shipped is Denver hourly rainfall (July, 1949–1990) from the R package extRemes (GPL): see `data/third-party/README.md`.

### What it does
- **Quality control:** gaps, negative and implausible values, flat-lined sensors, long dry runs in wet months, record length, Mann–Kendall trend test, and a record-strip chart.
- **Annual maxima:** sliding (rolling) windows for any durations (default 5 min to 48 h), calendar or water year, coverage rules, a fixed-interval (Hershfield) correction, and the empirical correction factor when sub-daily data exist.
- **Frequency analysis:** Gumbel, GEV, Log-Pearson III, Log-Normal (2- and 3-parameter), Gamma, Pearson III and GLO, fitted by L-moments, moments or maximum likelihood (GEV also by L-moments with a fixed shape, and by penalised likelihood, experimental). Candidates ranked by AICc, BIC, Anderson–Darling, probability-plot correlation or KS; plotting position of your choice; per-duration overrides; L-moment ratio diagram; bootstrap confidence intervals; parametric-bootstrap p-values.
- **Peaks over threshold:** independent storms above a threshold, generalised Pareto or exponential excesses (L-moments or ML), Poisson conversion to annual return periods, a threshold-stability table, and the option to use the result for design.
- **Screening:** Mann–Kendall trend test with Sen’s slope, and Grubbs–Beck outlier flags.
- **IDF equations:** the Koutsoyiannis et al. (1998) general IDF (Gumbel/GEV; robust, one-step least-squares and likelihood estimation), plus Talbot, Bernard, Sherman, Kimijima, a general four-parameter form and three unified-in-T forms. Fitting uses multi-start and differential-evolution optimisation, and models are compared with R², RMSE, NSE, KGE, bias, maximum error, AICc, overfitting warnings and bootstrap parameter intervals. The default choice is explained on screen.
- **Short durations from daily data:** IMD formula, calibrated power law, simple scaling, depth-ratio transfer from a nearby sub-daily station, your own ratio table, and Bell (experimental), shown side by side, with a one-click hold-out test on any station that has sub-daily data.
- **Adjustments:** climate-change uplift (% or %/°C, optionally larger for short durations) and areal reduction, shown beside the baseline.
- **Design storms:** alternating block, Chicago, SCS Type I/IA/II/III, Huff quartiles, triangular and uniform; export to CSV, SWMM (rain file and `[TIMESERIES]`) and HEC-HMS.
- **Several stations:** side-by-side curves, regional L-moment statistics, and inverse-distance estimates at a point (both experimental).
- **Outputs:** log-log and semi-log curves, intensity and depth tables, equations with units, PNG/SVG figures at a chosen size (cm) and DPI, XLSX/CSV/JSON, and an HTML report that states every choice and cites the methods.

## Publishing in the portfolio

The folder is built to sit at `tools/brishti-idf/` in the `meawman.github.io` repository. It links the portfolio’s `assets/favicon.svg` and `assets/css/tool-shell.css` with `../../`, and stores the theme under the portfolio’s key `mrj_theme`.

1. Copy **the contents of this folder** to `tools/brishti-idf/` in the portfolio repository.
2. Add the card for the Tools section to `data/content.json` (the entry is in `PORTFOLIO_ENTRY.json`; the admin page can paste it too).
3. Commit and push. GitHub Pages serves it at `https://meawman.github.io/tools/brishti-idf/`.

There is no build step: the files are served as they are. `tests/`, `tools/` and `docs/*.json` are not needed on the site but are harmless; leave them in the source copy so the checks can be repeated.

**Offline:** after one visit, the tool keeps working without internet (a service worker, `sw.js`, stores the files in the browser).

### Running it on your own computer
Browsers do not run JavaScript modules from `file://`, so double-clicking `index.html` will not work. Start a small local server in this folder instead:
```
python3 -m http.server 8000
```
and open http://localhost:8000. (Served on its own, the portfolio header and favicon are missing; everything else works.)

## For developers and reviewers

### Folder layout
```
index.html            page shell
css/style.css         styles (light/dark theme tokens)
css/portfolio.css     portfolio palette, header, “i” buttons and Methods screen
js/app.js             application state, Web Worker management, navigation
js/pipeline.js        the full analysis for one station (runs in the worker)
js/core/              numerics, no DOM: special functions, RNG, statistics, distributions, optimisers,
                      time series & AMS, IDF models, disaggregation, design storms, adjustments,
                      regional analysis, uncertainty, synthetic generator
js/io/                parsing (CSV/XLSX layouts) and export (CSV, XLSX, JSON)
js/plot/plots.js      all charts (Plotly)
js/ui/                DOM helpers, the step screens, info.js (the “i” texts) and methods.js (Methods screen)
js/report/report.js   HTML methods-and-results report
js/worker/worker.js   Web Worker entry (heavy jobs; cancellable)
sw.js                 offline support
vendor/               Public Sans font (with licence); Plotly 3.2.0 and SheetJS 0.18.5 are shared with the
                      other portfolio tools in ../../assets/vendor/ (with licences)
data/                 synthetic sample files; data/third-party/ real Denver record
tests/                Node test-suite; tests/reference/ SciPy reference generator
tools/                hold-out study, validation report, browser smoke test, sample generator
docs/                 validation, hold-out results, limitations
DECISIONS.md          design decisions and why
```
Every numerical routine lives in `js/core/` as a plain, commented ES module, so a hydrologist can read or change a formula without touching the interface.

### Tests and validation
Requires Node.js 20 or newer; there are no npm dependencies.
```
npm test                          # the full test-suite (see docs/VALIDATION.md for the counts)
node tools/run_validation.js      # runs the tests and rewrites docs/VALIDATION.md
node tools/holdout.js             # re-runs the daily-to-sub-daily hold-out, rewrites docs/HOLDOUT.md
python3 tests/reference/make_reference.py   # regenerates SciPy reference values (needs SciPy)
node tools/browser_smoke.cjs out/ # drives the UI in headless Chromium (needs Playwright)
SITE_ROOT=<portfolio> BASE=/tools/brishti-idf/ node tools/browser_smoke.cjs out/   # the same, inside the portfolio
```

### Design choices
See `DECISIONS.md`. In short: the numerics are pure JavaScript, verified against SciPy, instead of Pyodide (fast load, works offline, readable); the Koutsoyiannis general IDF is the primary model; and anything that could not be verified from a source is labelled **EXPERIMENTAL** in the interface.
